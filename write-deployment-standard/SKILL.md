# 部署标准文档编写

编写可按步骤执行、可核对结果的部署文档。以用户指定的产品版本、资料、格式和最新文件为依据。

## 输入与修改基准

- 先确定交付格式、产品版本、文档范围及可用资料。模板仅在用户提供或要求时使用。
- 有模板时，参考其章节层级、字体、段落、页眉页脚和代码样式；无模板时，按产品部署流程组织内容，保持样式统一。
- 官方资料和随包配置用于核对参数含义、语法及产品默认值；现场配置用于提取项目值。资料冲突时核对版本和用户约定，缺失值明确标记为待确认。
- 修订以用户最新保存的文件为基准，局部修改，保留用户手工调整的内容及格式。避免使用旧稿或旧生成脚本整体覆盖。
- 用户要求备份时，明确所备份的版本，保留原文件并核对备份内容；最初版本应来自可验证的历史文件。

## 内容与参数

- 主体覆盖单产品的标准部署；集成组件、项目链路和特殊参数放入特殊场景章节。具体章节按任务需要安排。
- 标准配置模板应包含对应版本、所述部署模式所需的完整配置段和字段。核对随包模板中的关键参数，补齐被简写的字段，保留应有的启停状态。
- 明确区分产品默认值、推荐值、项目值和示例值。实例名、队列名、地址、端口、路径等按实际用途标识，项目名称应注明为示例。
- 关键参数说明用途、单位和取值依据；具有业务差异的参数，标准章节仍应包含该参数及调整原则，特殊章节再给出项目取值。
- 参数存在关联时，说明需要同步修改的文件、配置段和字段，核对链路两端及中间组件的限制。关联产品的参数按各自语义计算，例如消息头占用可能影响消息长度上限。
- 安装目录、用户家目录、产品根目录分别说明，并核对命令、环境变量和配置中的引用一致。环境变量应在依赖它的步骤前设置。

## 操作与文字

- 使用简洁、直接的手册语言，说明操作对象、动作和结果。删除重复解释、抽象措辞及无必要的否定式描述，避免用“派生”等词增加理解成本。
- 每组命令交代执行用户、必要的工作目录和目的；在相邻文字中给出预期输出、状态或明确的判断标准。
- 检查命令按检查对象分组，说明合格条件。避免连续罗列大量命令而缺少结果解释。
- 仅执行一次、覆盖或追加文件、重新登录等会影响执行结果的要求，紧邻相应步骤说明。
- 配置块前写明完整文件路径及修改位置，例如配置段、XML 节点或现有记录。
- 配置使用原生语法、层级和缩进，必要参数后加简短功能注释。注释应符合文件语法；格式不支持注释时，将说明放在代码块外。

## Word 排版

- 命令和配置沿用指定模板的代码样式；没有模板时，采用清晰、统一的单格外框代码段。
- 一个连续代码段使用单行单列的框，仅保留外框。所有换行和缩进在同一格内完成，避免每行分格或用冗杂表格替代原生配置。
- 代码段取消项目符号和自动编号。需要填写、修改或同步的配置项标红，普通默认项及注释保持正文颜色；标红范围应明确对应所需改动。
- 检查长行折行、缩进、代码框跨页及图示清晰度，避免参数名、地址和标签被拆成难以阅读的片段。
- 若环境提供文档编辑技能或渲染工具，使用其格式处理和渲染流程。交付前渲染并逐页检查；无法渲染时说明验证范围。

## Markdown 排版

- 命令和配置直接使用围栏代码块，标注合适的语言，例如 `bash`、`ini`、`yaml`、`xml`、`properties`；保留原生换行和缩进。
- 配置使用其实际格式，INI 或 XML 等内容保持对应语法。
- 需要修改、填写或同步的项，通过合法注释或紧邻代码块的说明标识。用户要求颜色时，再按目标渲染器的支持情况处理。
- 核对代码围栏配对、标题层级、列表、相对链接及代码块显示；不要套用 Word 的单格表格排版。

## 链路与图示

- 涉及多组件时，先理清连接关系和消息的发送、读取关系，再写配置或绘图。用户要求先出图时，先交付图示。
- 明确谁发送、谁读取、使用哪个队列或组件；区分连接方向与消息流向，必要时用箭头标签或图例说明。
- 图中同一模块只出现一次，复用节点表达多条链路。不同业务方向清晰分区，节点对齐，分支尽量对称，标签完整。
- 按用户指定的链路边界结束图示。用户确认的图示按要求插入文档，后续修订保持其内容。

## 交付检查

- 核对正文、命令、配置、图示中的路径、实例名、端口、队列及关联参数一致；检查示例值和特殊值的标识。
- 检查每组操作都有预期结果，关键配置都注明路径，需要调整的项有对应标识。
- 与最新输入比较，确认修改限于本次范围，用户手工修改得到保留。完成对应格式的内容与版式检查后交付。
- 仅编写文档时，验证限于资料、文件及渲染结果；实际部署、连接生产系统或执行文档中的运维命令须有相应任务授权。
