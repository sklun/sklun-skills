# 从云文档整理任务多维表格

## 设计与预览

1. 用 `docs +fetch --as user --doc <链接>` 获取与任务相关的正文。需要把链接定位到具体条目时，用 `--doc-format xml --detail with-ids` 获取块 ID。知识库链接用于导航，底层对象 token 用于对应 API。
2. 以可独立跟踪的工作为记录。优先复用原有分类和已有规范链接。根据任务选择名称、分类、主负责人、描述、关联文档、起始日期和等级。状态、截止日期或额外字段按需求补充。仅出现章节标题或问题汇总链接时，先确认有可跟踪的动作再生成记录。
3. 真实记录只填有依据的值。「年底前」「2 月底前」等未给出确切年份的要求保留在描述里。负责人、日期、状态或等级缺失时留空，除非用户给出初始化规则。静态样式预览可用明确标注的示例，实际写入从原文和值映射生成。
4. 只要求方案或预览时，在对话或本地交付。用户确认创建后，再执行远程写入。

## 创建与核验

- 用 `base +base-create --name <多维表格名> --table-name <数据表名> --fields <字段数组> --as user` 创建 Base 和首表。根据当前 `lark-base` 的字段指南选择文本、人员单选、日期、单选和超链接等类型。需要指定时区时，本机使用 `Asia/Shanghai`。
- 用 `base +field-list` 核对实际可写字段，再用 `base +record-batch-create` 录入，保存返回的表、视图和记录 ID。若写入结果不明确，先查询现状再决定是否重试，避免重复建表或录入。
- 按用户确认的方案配置视图。例如总览用 `+view-set-group` 配置分类，进度看板按状态分组。涉及「未完成且为高优或临近到期」这类复合筛选时，先看当前筛选协议。若仅支持单层 AND/OR，可用可核验的公式字段计算关注标记，再用视图筛选。无截止日期的任务按实际优先级判断。
- 回读记录数、任务名称、分类、链接和预期留空字段。有视图配置时同时核对实际列、分组和筛选。调整已有表前读取当前值，只改本次请求涉及的字段或视图。

## 移入知识库

- 目标是「与原文同级」时，用 `wiki +node-get --node-token <原文链接> --as user` 获取空间和父节点。对于已有云空间 Base，用 `wiki +move --obj-type bitable --obj-token <Base token> --target-space-id <空间 ID> --as user`。原文有父节点时加 `--target-parent-token <父节点 token>`，位于根目录时省略。
- 分清移动与添加来源链接。用户要求与原文无关联时，将 Base 放在目标层级的独立节点，清理表里指向原文的链接，保留仍有用的独立规范链接。准备日后替换原文时，只执行本次指定的迁移与调整。原文编辑、归档和删除分别以用户的明确请求为准。
- 移动返回任务 ID 且尚未就绪时，按 CLI 输出继续查 `drive +task_result --scenario wiki_move`。完成后通过新 Wiki 节点核对空间、父节点和底层 Base token，回读记录，并交付新的知识库链接。

## 只调整展示

- 列顺序用 `base +view-get-visible-fields` 读取，再用 `+view-set-visible-fields` 提交目标视图完整的可见字段列表。未指定的列保留相对顺序。主字段可能固定在首列，以回读的实际顺序为准，避免为调整展示而改主字段或重建表。
- 列宽、行高、自适应与列顺序是不同能力。先核实当前 CLI 和公开接口是否支持目标操作。只有界面支持且本次允许使用界面时，按当前可用权限尝试并核验。说明具体已完成与未完成的设置。
